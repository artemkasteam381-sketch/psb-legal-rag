# Ассистент по договорам и регламентам

Портфолио-проект по кейсу ПСБ «Юридический ассистент» на Hack&Change 2026. Ассистент принимает вопрос и дату, ищет применимые положения договоров и внутренних регламентов, показывает цитаты с названиями файлов и номерами строк. Один запрос может объединять несколько условий, в том числе из договора и регламента. Если основания есть только для части запроса, ответ показывает найденное и указывает, что осталось без подтверждения.

## Запуск

Требуется Python 3.10 или новее. Используется стандартная библиотека, ключи и сеть не нужны.

```bash
python3 cli.py ask 'Какие документы нужны для приёмки по договору ДП-17-2025 и кто согласовывает расхождения по регламенту?' --date 2025-03-15
python3 cli.py ask 'Какие документы нужны для приёмки по договору ДП-17-2025 и кто согласовывает расхождения по регламенту?' --date 2025-04-01
python3 cli.py ask 'Какой штраф за просрочку оплаты по ДП-17-2025?' --date 2025-07-01
python3 evaluate.py --details
```

В первых двух ответах перечень документов берётся из [п. 4.1 договора](data/documents/dp-17.md). На 15 марта расхождения согласовывает начальник склада по [старой редакции регламента](data/documents/rg-02.md). С 1 апреля это делает руководитель отдела закупок по [новой редакции](data/documents/rg-02-v2.md). В третьем примере в договоре есть штраф за просрочку поставки. Для штрафа за просрочку оплаты система сообщает об отсутствии подтверждения.

Чтобы посмотреть ранжирование до отбора цитат, запусти команду ниже. Значения `--mode` — `bm25`, `document` и `versioned`. Дату также можно указать в тексте вопроса. При расхождении дат система просит уточнить запрос.

```bash
python3 cli.py search 'Какой срок оплаты по ДП-17-2025?' --date 2025-07-01 --mode versioned
```

## Как проходит запрос

1. [cli.py](cli.py) передаёт вопрос и дату в `rag.answer()`.
2. [rag.py](rag.py) делит составной запрос на части и определяет документ для каждой. Слова «по договору» или «по регламенту» задают тип источника. Если в базе несколько подходящих документов, нужен номер.
3. Каталог [data/catalog.json](data/catalog.json) связывает редакции с документом и отмечает, какие пункты заменились. `Search.active_clauses()` оставляет пункты, действовавшие на дату события. Неизменённые пункты продолжают действовать при выходе следующей редакции.
4. BM25 отбирает до пяти фрагментов на часть вопроса. Из них остаются пункты, покрывающие ключевые слова из запроса после нормализации. Если таких пунктов несколько, преимущество получает тот, чьё название покрывает больше ключевых слов. При равенстве сохраняется порядок BM25. CLI печатает оригинальные цитаты, ссылки на пункты и интервалы действия.
5. [evaluate.py](evaluate.py) проверяет сравнение режимов и итоговые ответы по [разметке](data/evaluation.json).

## Результаты

Три режима используют одно разбиение запроса, один индекс и одинаковые правила отбора цитат. Режим `document` отбирает пункты из нужного документа во всех редакциях. `versioned` оставляет только действующие пункты. Это позволяет отдельно измерить вклад даты.

В корпусе 4 договора, 1 регламент, 10 файлов с учётом редакций и 26 фрагментов. Проверено 53 сценария, включая 36 с источниками, 9 без оснований для ответа и 8 на уточнение.

| Поиск | Recall@5 на часть | Топ-1 всех частей | Точные ссылки в ответе | Цитата там, где ответа нет |
|---|---:|---:|---:|---:|
| BM25 | 100% | 38,9% | 16/36 (44,4%) | 3/9 |
| BM25 + документ | 100% | 38,9% | 17/36 (47,2%) | 2/9 |
| BM25 + документ и дата | 100% | 77,8% | 36/36 (100%) | 0/9 |

Recall@5 — средняя доля размеченных источников в объединении топ-5 по частям вопроса. «Топ-1 всех частей» требует, чтобы объединение первых результатов совпадало со всеми ожидаемыми источниками. «Точные ссылки в ответе» проверяют совпадение уже выбранных цитат. Все 53 локальные проверки итогового режима прошли. Проверяется статус, точный набор ссылок, дословность цитат и контрольные фразы.

- **Устаревшая редакция.** Поиск в нужном договоре может вернуть первоначальный срок оплаты в 30 календарных дней вместо 10 рабочих. Дату учитывает фильтр пунктов.
- **Близкий, но другой пункт.** На вопрос о сроке приёмки BM25 поднимает список документов для приёмки. Выбор с учётом заголовка отдаёт приоритет самому пункту о приёмке.
- **Нет одного основания.** В запросе о штрафе по ДП-71-2025 и согласовании расхождений поиск находит пункт о поставке, хотя штрафа там нет. Ассистент цитирует только регламент и сообщает, чего не хватает по договору.

Корпус и сценарии синтетические. У каждого документа в демо до пяти действующих пунктов, поэтому Recall@5 здесь мало различает режимы. Точность ссылок измерена на этом наборе. Проверки на новых документах и свободных перефразированиях в результат не входят.

## Допущения

- Документы представлены как Markdown с заголовками пунктов. Связи редакций и даты вступления в силу задаются вручную в каталоге. Граница следующей редакции исключается из интервала прежней.
- Один запрос использует одну дату и до одного договора и одного регламента. Составные вопросы делятся по союзам и знакам препинания. Сложные синтаксические конструкции и перефразирования могут потребовать уточнения.
- Ответы экстрактивные. Для нормализации словоформ используется лёгкая эвристика и несколько групп синонимов. Покрытие слов помогает отсеивать неподходящие цитаты, но оно ограничено лексическим совпадением.
